# U1000 Omega_m target-table creation audit

Decision: **GO** for target-table production readiness. No U1000 or repository production graph build occurred.

## Authoritative source and extraction

The authoritative source is the CAMELS-SIMBA raw halo-catalogue header in `data/raw/CAMELS_SIMBA_1000U/LH_<index>_hlist_<snapshot>.list`. The exact header is `#Omega_M = <value>; Omega_L = <value>; h0 = <value>` and the exact parsed key is `Omega_M`. Universe identity comes from the `LH_<index>` filename prefix. The repository-established extractor is `src.data.inspect_targets`, whose anchored regular expression reads `Omega_M` from header comments and whose CSV contract names the target column `omega_m`.

For each integer index 0 through 999, extraction required exactly these filenames: `0.20000`, `0.25000`, `0.51209`, `0.75065`, and `1.00000`. The production row was accepted only after all five independently parsed header floats were exactly equal. No averaging, inference, interpolation, extrapolation, or simulation was used.

Inventory evidence: 5,000 `.list` files; exactly 1,000 filename-derived universe IDs; exactly five required snapshot identities per universe; no missing, extra, or unknown identities. Each tested catalogue contained exactly one parseable `Omega_M` header.

No independent CAMELS simulation-parameter table exists in the repository or raw directories. Therefore independent-parameter-file consistency is not applicable. The separately existing U750 target table provides an independent repository-artifact prefix check, and all 750 values match exactly.

## Builder interface audit

The temporal sparse builder CLI argument is `--targets_csv`. It accepts the ID columns `universe_id`, `Universe`, `universe`, `Universe_ID`, `lh_id`, or `LH`; it accepts targets `omega_m`, `Omega_m`, `Omega_M`, `target`, `Target`, or `omega_m_value`. IDs may be integers, numeric strings, or case-insensitive `LH_<integer>` strings; targets are converted by `float`. The return value is `Dict[int, float]`, and graph-build iteration maps numeric universe index to its scalar target, independent of CSV row lookup order.

The parser itself silently applies last-row-wins behavior to duplicate IDs, retains unknown numeric IDs that a requested build would ignore, and does not reject missing requested IDs until build iteration (where a missing target becomes a failed universe unless a dummy target was separately supplied). Those interface weaknesses were not modified in this target-only task. The authoritative table was therefore strictly prevalidated before the parser check: no duplicate, missing, or unknown IDs, exact numeric order, and finite values.

No U1000 or repository production graph builder, split generator, experiment generator, trainer, checkpoint writer, or prediction writer was invoked. A subsequently run broad `test_source_manifest_integrity.py` suite unexpectedly exercised its one-universe synthetic sparse-builder fixture under a temporary directory; that fixture invoked periodic kNN, created a temporary toy graph dataset, and was automatically deleted. It did not read the U1000 raw corpus, did not use this U1000 target table, and left no graph artifact in the repository. This was a procedural exception to the requested target-only test scope; the direct target-entry manifest test and direct builder-parser test had already passed without graph construction.
